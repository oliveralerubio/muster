# Muster

Muster syncs machines, AI coding agent configuration and secrets from one Git
repository, so a person or a team gets the same agents everywhere without
handing API keys around.

## Language

### Fleet

**Machine**:
A device enrolled in the fleet, with its own age keypair. The private key lives only in that machine's local state; the public key is registered in the manifest.
_Avoid_: host, node, device

**Fleet**:
All machines that share one config repository.
_Avoid_: cluster

**Enrollment request**:
A file a new machine writes into the config repository with its public key and metadata. It stays pending until an authorized approver accepts it.
_Avoid_: signup, registration

**Enrollment approval**:
The act of accepting an enrollment request, which adds the machine's public key as a vault recipient. In team mode it is subject to the quorum.
_Avoid_: authorize, accept (use "approve")

**Recovery key**:
An offline identity generated by `muster init`. It is a recipient of every secret group, is shown once, and is never stored on any machine.
_Avoid_: backup key, master key

### Secrets

**Vault**:
The age-encrypted files in the config repository that hold all secrets: one ciphertext file per secret group plus plaintext metadata sidecars with no values. No server or account is involved.
_Avoid_: secret store, password manager

**Secret group**:
A set of secrets encrypted as one unit for its own list of recipients (members, groups, machines or raw recipients). A non-recipient cannot decrypt it.
_Avoid_: collection, bucket

**Member**:
A person in team mode who owns machines and holds a role (admin or member). Joined through a pending invitation approved by admins.
_Avoid_: user, collaborator

**Quorum**:
The number of distinct admins required to approve an enrollment or an invitation (`[team] required_approvals` in `muster.toml`, at least 1, default 1). Each approval is recorded with the admin's name; the same admin never counts twice; the recovery key counts as a full approval on its own.
_Avoid_: threshold

**Secret access (`allow`)**:
The deny-by-default rule that decides which agents may receive a secret: `[secrets."<reference>"] allow` in `muster.toml`, with `agent` for everywhere or `agent@project` for one project. Three distinct states, never flattened: no policy declared (agents never receive it; the human CLI still can), an explicit empty list `allow = []` (deny everyone), and a list of allowed agents.
_Avoid_: whitelist

**Secret request**:
A pending request for a named agent to use a secret whose policy requires human
approval. Stored locally with the reference and agent, never the value.

**Lease**:
A local human approval for one secret reference and agent, reusable until its
expiry or revocation. It does not invalidate credentials already delivered.

### Agents and skills

**Effective configuration**:
The configuration selected for a machine or project after layers are merged, together with its origins and per-adapter state on disk.

**Adapter**:
The per-agent translator (Claude Code, Codex, OpenCode, Antigravity CLI, Pi) that renders the canonical configuration into the agent's native files, declaring which files, capabilities, platforms and minimum version it supports. It rewrites only the keys it manages.
_Avoid_: plugin, driver

**Capability**:
A canonical feature an adapter may support: instructions, stdio MCP servers, remote MCP servers, models, permissions, hooks, skills, subagents, packages (Pi only; `[agents.packages]`), AI providers (`providers`). Configuration using a capability an adapter lacks is applied only where supported, with an `unsupported_feature` warning.
_Avoid_: feature flag

**AI provider**:
A named model endpoint in `[providers.<id>]`, with a kind, optional base URL, default model and secret key reference. An agent selects an AI provider through `[agents.providers]`. This is distinct from a secret provider (the backend that resolves secret references).
_Avoid_: "provider" unqualified when it could mean a secret provider

**Profile**:
A named configuration profile assigned to members, groups or machines; the fixed precedence is team → group → member → machine → project.
_Avoid_: preset, config layer

**Instruction overlay**:
An `AGENTS.<agent-id>.md` file beside the canonical instructions that adds instructions for one agent.

**Managed block**:
The region of a Markdown file delimited by `BEGIN`/`END MUSTER MANAGED BLOCK` markers that Muster replaces on every apply; the rest of the file is preserved as the user wrote it. In JSON and TOML files the managed unit is the keys and sections Muster declares.
_Avoid_: heredoc, section

**Skill**:
An Agent Skills folder (`SKILL.md` with `name`/`description` frontmatter plus any files) installed for every capable agent. Own skills live in the config repository's skills folder; subscribed skills are copied there too.
_Avoid_: plugin, extension

**Unmanaged skill**:
A skill folder found in an enabled agent's own skills folder (for example `~/.claude/skills/<name>`) that is neither in the config repository nor built in. `muster skill list` reports it under `unmanaged`, with its `source` when the `npx skills` lock (`~/.agents/.skill-lock.json`) says which repository it came from. `muster skill import` subscribes to that repository when the source is known (so it keeps receiving updates) and otherwise copies it in as an own skill; `--all` does every importable one in a single commit. The original files stay untouched.
_Avoid_: orphan skill, foreign skill

**Auto-update**:
The opt-in `[agents.skills] auto_update` setting: `muster sync` updates subscribed skills unattended, between pull and push. Locally modified skills are skipped, never forced, and it is separate from the global `--yes`.
_Avoid_: auto-upgrade

**Vendored skill**:
A skill copied from an external Git repository into the config repository's skills folder, so the engine and adapters treat it exactly like an own skill and every machine receives it through the normal sync.
_Avoid_: downloaded skill, cached skill

**`skills.lock`**:
The versioned TOML file next to `muster.toml` that pins each skill's `origin` (`local` or the source id), upstream `commit`, `content_hash`, `version` and `updated_at`. Apply verifies each skill against this hash; missing or mismatching pins skip the skill and keep its previous copy. Authors explicitly accept own-skill edits with `muster skill pin <name>`.

**Skill status**:
The last known state of a subscribed skill: `local`, `up_to_date`, `update_available`, `deprecated` (upstream frontmatter marks it deprecated; wins over `update_available`), `upstream_removed`, or `unknown` (never checked, or the source was unreachable at the last `skill check`, which reports `unknown` and keeps the cached last-known status so an offline `skill list` still shows it). Separately, a skill whose files no longer match `skills.lock` is reported with the boolean `modified: true` — a flag, not a lifecycle status; `skill update` refuses to overwrite it without `--force`. Unreviewed skills (missing pins or changed hashes) are skipped by sync, reported separately in convergence, and keep their previously installed copy; this is not another lifecycle status. Empty directories are ignored. Upstream changes still require an explicit command.

### Operations

**Sync**:
The act of exchanging the config repository with its Git remote and applying the desired state with backups and a generation (`muster sync`). This is how every machine converges.
_Avoid_: deploy, push (unqualified)

**Schedule**:
The periodic execution of sync through a systemd user timer (Linux/WSL), a launchd agent (macOS), or manual instructions when neither is available (`muster schedule`). An unattended sync never installs agent binaries, even previously approved versions: it keeps the current binary, applies configuration and verified skills, and records approval needed. New hooks or MCP servers still cause it to refuse and wait for a person.

**Convergence**:
Whether this machine matches the desired fleet configuration: agent versions against pins, skills verified against `skills.lock`, and pending approvals. CLI status, the web panel and MCP share one report; unsupported agent platforms remain visible as not converged.

**`muster.lock`**:
The versioned TOML file pinning agent CLI versions. Each agent pin has optional per-platform artifacts with a source URL and SHA-256, and an optional installed binary name; legacy top-level `url`/`sha256` remain a platform-independent fallback. Binaries are verified before atomic replacement.

**Generation**:
A numbered snapshot in local state of every managed file after an apply. Rollback restores the exact files of a previous generation and records the restoration as a new generation.
_Avoid_: version, revision

**Toggle**:
A layer's enable or disable rule for a named skill, MCP server, or subagent,
optionally limited to one adapter. Toggles control deployment and do not change
`skills.lock`.

**Usage report**:
A local summary of observed skill, MCP server, and subagent calls in agent
session transcripts. An unused item has no observed calls in the selected
window; incomplete transcript coverage does not prove it was never used.
